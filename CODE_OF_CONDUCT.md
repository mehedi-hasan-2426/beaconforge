# Code of Conduct

BeaconForge welcomes people with different backgrounds and experience levels.
Beginners should be able to ask questions, and contributors should be able to
disagree about technical choices without being personally attacked.

## Expectations

- Be respectful and specific. Discuss the code, evidence, and tradeoffs.
- Give constructive feedback and leave room for correction.
- Do not harass, threaten, discriminate, or make personal attacks.
- Do not publish another person's private information without consent.
- Avoid spam, pressure for unpaid work, and misleading claims about verification.

These expectations apply to project issues, pull requests, discussions, and other
spaces maintained for this project.

## Raising a Concern

For a non-sensitive moderation concern, ask a maintainer for help in the relevant
project space. For a sensitive report, ask for a private contact route without
publishing names, personal information, or the report's details.

There is no dedicated private moderation channel configured before publication.
Security vulnerability reports belong under [SECURITY.md](SECURITY.md), not in a
public conduct complaint.

## Maintainer Responsibilities

Maintainers should consider reports fairly, keep sensitive details private, and
explain moderation decisions where appropriate. Responses may include a request
to edit a message, removal of harmful content, a warning, or restricting access
to project spaces.

This is an original, lightweight policy for BeaconForge, not an assertion of a
formal enforcement team or a guaranteed response time.
